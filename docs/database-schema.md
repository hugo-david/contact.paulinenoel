# Proposition de schéma PostgreSQL

## Table `quote_requests`

Une seule table porte l’agrégat **demande enregistrée**. Ce choix correspond à la fonction d’archive fiable : aucun compte, prospect, catalogue administrable ni reporting relationnel n’est prévu.

| Colonne | Type PostgreSQL | Règle | Rôle métier |
| --- | --- | --- | --- |
| `id` | `bigint generated by default as identity` | clé primaire | Identifie la demande enregistrée. |
| `full_name` | `text` | requis | Nom du prospect. |
| `email` | `text` | requis, non unique | E-mail du prospect ; une même adresse peut créer plusieurs demandes. |
| `phone` | `text` | facultatif | Téléphone fourni par le prospect. |
| `company_name` | `text` | facultatif | Entreprise fournie par le prospect. |
| `website_url` | `text` | facultatif | Site web fourni par le prospect. |
| `project_description` | `text` | requis | Description libre du projet. |
| `desired_timeline` | `text` | requis | Délai souhaité (`flexible`, `normal` ou `express`). |
| `selections` | `jsonb` | requis | Instantané des prestations, options et quantités choisies. |
| `estimate_lines` | `jsonb` | requis | Instantané des lignes d’estimation affichées. |
| `estimate_low_cents` | `integer` | requis, ≥ 0 | Borne basse de l’estimation en centimes d’euro. |
| `estimate_high_cents` | `integer` | requis, ≥ 0 | Borne haute de l’estimation en centimes d’euro. |
| `currency` | `char(3)` | requis, `EUR` | Devise de l’estimation. |
| `notification_status` | `text` | requis | État de la notification : `pending`, `sent` ou `failed`. |
| `notification_attempted_at` | `timestamptz` | facultatif | Date de la dernière tentative d’e-mail. |
| `notification_sent_at` | `timestamptz` | facultatif | Date d’envoi réussi de l’e-mail. |
| `notification_error` | `text` | facultatif | Dernière erreur technique d’envoi, si utile au diagnostic. |
| `last_contact_at` | `timestamptz` | requis | Point de départ de la conservation ; initialisé à la soumission. |
| `purge_after` | `timestamptz` | requis | Date de suppression prévue, trois ans après le dernier contact. |
| `created_at` | `timestamptz` | requis | Date d’enregistrement. |
| `updated_at` | `timestamptz` | requis | Date de dernière mise à jour technique. |

## Contraintes

- `estimate_high_cents >= estimate_low_cents`.
- `currency = 'EUR'` pour cette version française.
- `notification_status` est limité à `pending`, `sent` et `failed`.
- `email` n’est pas unique : deux demandes d’un même prospect restent indépendantes.
- `selections` et `estimate_lines` ne sont jamais réécrits après la soumission, afin de préserver l’estimation historique.

## Index

- `purge_after` : pour traiter la suppression des demandes arrivées à échéance.
- `notification_status` : pour repérer les notifications à envoyer ou échouées.
- `created_at` : pour l’exploitation technique de l’archive.

Aucun index JSONB ni index sur l’e-mail n’est proposé : l’application ne comporte pas de recherche ni de reporting dans cette première version.

## Éléments volontairement absents

- table `prospects` ;
- table `service_catalog` ;
- table `quote_request_items` ;
- table `email_notifications` ;
- toute table de compte ou d’administration.

Ces éléments ajouteraient des relations utiles pour un CRM, un back-office ou du reporting, qui ne font pas partie du périmètre actuel.
